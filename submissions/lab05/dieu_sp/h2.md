## Question

**Do degraded or unresolved answers get worse feedback than normal answers?**

Why it is useful: the assistant falls back to a degraded answer (e.g. the LLM is down) or answers `unknown`. If students
rate those answers much lower, improving the fallback path is worth more than tuning answers that already work. It
also checks that the `resolved` / `degraded` flags we record in `interaction` are worth storing.

## Query

```sql
SELECT
    CASE
        WHEN i.resolved = 0 THEN 'unresolved'
        WHEN i.degraded = 1 THEN 'degraded'
        ELSE 'normal'
    END                                              AS answer_kind,
    COUNT(*)                                         AS feedback_count,
    SUM(f.rating = 1)                                AS thumbs_up,
    SUM(f.rating = -1)                               AS thumbs_down,
    ROUND(100.0 * SUM(f.rating = 1) / COUNT(*), 1)   AS pct_up
FROM feedback AS f
JOIN interaction AS i ON i.request_id = f.request_id
GROUP BY answer_kind
ORDER BY pct_up DESC;
```

## Result

Run on a fresh database built with the Lab 5 starter scripts (synthetic data only):
`python scripts/migrate.py assistant.db` then `python scripts/seed.py assistant.db 300`
(300 interactions, 59 sessions, 96 feedback rows).

```
answer_kind | feedback_count | thumbs_up | thumbs_down | pct_up
normal      | 70             | 61        | 9           | 87.1
unresolved  | 8              | 0         | 8           | 0.0
degraded    | 18             | 0         | 18          | 0.0
```

## What it tells us

- Normal answers get 87.1 % thumbs-up; every rated degraded or unresolved answer got a thumbs-down.
- 26 of the 96 ratings (27 %) are about degraded or unresolved answers, so the fallback path matters.
- On seeded data the 0 % is built into `seed.py` (only good answers can get a thumbs-up). On real data the same
  query shows whether the degraded fallback is "good enough" or needs work.
- No raw text is needed: the query uses only `rating`, `resolved` and `degraded`.
